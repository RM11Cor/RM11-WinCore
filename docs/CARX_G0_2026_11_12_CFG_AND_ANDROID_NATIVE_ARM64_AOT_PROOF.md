# CarX Street: G0 original x86 CFG and genuine Android ARM64 Bionic AOT build

Checkpoint: November 12, 2026. Branch: carx-street-pc-port-v1.

## Owner-supplied original game evidence and remaining unknown source

Original GameAssembly.dll is a Windows PE/x86-64 native IL2CPP DLL.
The previously user-exported v1.0 archive contained 256 original
Win64 exception-table function-code regions totalling 33,153 bytes,
each SHA256 validated. Many were epilogues or cold fragments,
and the original game logic has not yet been demonstrated executing.

PortLab v1.1 was successfully built and released with its original
permanent signing certificate and versionCode11:
https://github.com/RM11Cor/RM11-WinCore/releases/tag/carx-street-portlab-v1.1.0-original-win64-unwind-xdata-20261112

v1.1 exports the REAL corresponding UNWIND_INFO source metadata and
bounded CHAININFO parent records, not only the executable bytes.
The owner has NOT supplied the new v1.1 source ZIP to this checkpoint,
so no actual original CarX unwind chains have been verified here.

## Implemented during this work

1. A new bounded reachability-first x86-64 CFG disassembler at
   native-port/recompiler/x64_control_flow_gate.py.
   It decodes reachable instructions instead of padding and tracks:
   local/external calls, indirect calls/branches, local/external
   jumps, RIP-relative source-global references, invalid overlap,
   undecodable bytes, traps, missing returns and source fragments.

2. A fail-closed original code ZIP static compiler screener at
   native-port/recompiler/screen_carx_pdata_zip.py.
   Codegen now refuses original PE regions with unresolved external
   calls, indirect control flow, unsupported source globals,
   invalid control-flow overlap or partial/padded source regions.
   These are classified, never falsely reported as full functions.

3. Integration of source-unwind chain and code CFG status into
   native-port/recompiler/analyze_carx_win64_xdata_zip.py.
   The result reports safe original source offsets and structural
   categories without dumping proprietary machine code bytes.

4. A new native C ABI entrypoint carx_aot_run_u64 generated by
   native-port/recompiler/x64_function_aot.py. With the
   CARX_AOT_LIBRARY_ONLY compile flag, generated C++ can compile as
   an Android NDK shared library, instead of only a Linux CLI test.

5. New GitHub Actions Android NDK proof pipeline:
   .github/workflows/carx-aot-android-arm64-bionic-native-library.yml

   An original synthetic seven-byte Windows x64 function is lifted
   at build time to C++; actual Android NDK compiler
   aarch64-linux-android29-clang++ creates a real ELF64 AArch64
   ET_DYN native .so with exported carx_aot_run_u64 symbol.
   CI independently checked ELF architecture and symbol export.
   The result contains NO dynamic x86 decoder or FEX runtime.

   This proves Android/Bionic AArch64 build compatibility for the
   compiler output. It does NOT prove original CarX game code was
   translated or executed, nor game scene or phone launch.

## What constitutes the next actual CarX achievement

The next source-driven step is consuming user-owned
CarX_GameAssembly_AOT_Unwind_v1.1.zip from the already-published
PortLab v1.1. The code will validate all original source hashes,
decode real xdata/chain structures, inspect actual reachable x64
CFG and select viable source-function regions while rejecting
epilogues and unresolved imports.

The full G0 proof requires an actual callable GameAssembly method,
with original dependencies, executed on x86 reference and AArch64
with matching outputs. Only then should that real game method
be compiled for Android NDK/Bionic and tested on the REDMAGIC device.

No new generic inspector APK was created in this checkpoint.
No playable CarX port, actual Unity scene, vehicle simulation or
original gameplay frame has been demonstrated.
