# RM11 WinCore V1.4.1 — إصلاح صلاحية ضيف Box64 التجريبي

# RM11 WinCore V1.1 — تشغيل ARM64 ELF مستقل (ليس Wine/Box64)

**الجديد:** القسم 11 يختبر بدء **عملية Android ARM64 مستقلة** من ملف ELF PIE مضمن في APK، مع عرض exit code وstdout ومدة انتظار محدودة. هذه خطوة تنفيذ حقيقية تتجاوز اختبارات JNI، **لكنها ليست** دمج Wine/Box64 ولا تشغّل EXE أو ألعاب ويندوز.

**بناء GitHub تلقائياً:** ارفع `RM11-WinCore-v1.1.0-source.zip` إلى جذر المستودع. يستخدم `scripts-check.py` الـNDK المتوفر في سير العمل لبناء ELF المستقل *قبل* Gradle، ويتحقق `tools/verify_native_apk.py` من وجوده داخل APK. لا تحتاج تغيير workflow إن كان يختار أحدث ZIP ويشغّل `scripts-check.py` ثم Gradle.

**اختبار الهاتف:** بعد تثبيت APK افتح القسم **11** واضغط «تشغيل الملف التنفيذي ARM64». لا تحتاج حزمة الاختبار القديمة. توقيع APK يجب أن يطابق الإصدار المثبت كي يتم تحديثه دون حذف البيانات.

**تنبيه:** نجحت اختبارات C/Java المحلية، ولم يُختبر بناء APK الكامل أو تنفيذ ARM64 على REDMAGIC 11 Pro بعد. التفاصيل في `V11-ANDROID-EXEC-AR.md`. `versionName=1.1.0` و`versionCode=11`.

**الاختبار البرمجي:** `python3 scripts-check.py` ويشمل محاكاة JDK لمسار حفظ ZIP
وتأكيد رفض الملفات التالفة ومسارات traversal وحفظ الحزمة الصحيحة عند الفشل.

**غير متوفر:** Wine وBox64 وrootfs وDXVK وتشغيل EXE والألعاب وFPS الحقيقي.
المرحلة القادمة تستلزم الحصول على ثنائيات مرخصة ومبنية لأندرويد ومعالجة قيود

# RM11 WinCore V0.5-A — تحليل لعبة EXE ومقترح التوازن الذكي

**الجهاز المستهدف:** REDMAGIC 11 Pro / nubia NX809J / SM8850 / Adreno 840 / Android 16 / ARM64.


## جديد V0.8-A

عقب نجاح JNI في V0.7، تضيف هذه النسخة مكتبة `librm11runtime_adapter.so` ثانية داخل APK، ويحمّلها البرنامج ديناميكياً بواسطة `dlopen` ويفحص نسخة ABI ويستدعي اختباراً منها. هذه خطوة دمج حقيقية بين مكتبتين NDK، **وليست** دمج Box64 أو Wine. تحتاج الثنائيات الأصلية وبيئة تشغيل متوافقة قبل محاولة تشغيل EXE. تفاصيل الفحص وخطة الدمج في `V08-ARM64-ADAPTER-AR.md`.

## الجديد عن V0.4-A

1. **RM11 Smart Balance (Preview):** اختيار ملف Windows `.exe` من مدير الملفات عبر SAF.
2. محلل PE مكتوب بـ Java يعمل محلياً دون تنفيذ البرنامج، ويتحقق من البنية وحدود الأقسام ويقرأ حتى 8MiB.
3. رصد مكتبات الرسوميات الظاهرة في **جدول استيراد DLL** (D3D9/10/11/12 وVulkan وOpenGL) إن وُجدت.
4. اقتراح **أولي فقط** للدقة وهدف FPS ومسار DXVK/VKD3D مستقبلي، بناءً على الأدلة المحدودة من الاستيراد.
5. تصدير التقرير النصي للاختبار والمقارنة؛ إبقاء جميع فحوص V0.4 وحزم التدقيق كما كانت.
6. فحوص Java آلية لملفات PE تجريبية (x64/x86/Import Descriptor/بيانات تالفة).

## حدود أساسية — لا تُفهم النتائج خطأً

* **Wine وBox64 وDXVK وVKD3D غير مدمجين. لا تشغيل EXE في هذا الإصدار.**
* اسم ملف EXE أو مكتبات DLL المستوردة **لا يكفيان للتعرف على اللعبة يقيناً**؛ يمكن تحميل مكتبات الرسوميات وقت التشغيل أو استعمال أكثر من API.
* الأرقام المقترحة مثل 720p وهدف 30/60 FPS هي **إعدادات بدء غير مقاسة**، وليست نتيجة اختبار أداء أو توافق.
* لا يوجد بعد مقياس FPS داخل لعبة أو خوارزمية تعديل تلقائي حيّ للرسوميات والحرارة.
* لا يدعم تجاوز أنظمة مكافحة الغش. بعض الألعاب الأونلاين لن تعمل ولو نجح Wine.
* مراجعة التراخيص والتحقق من مصدر الثنائيات **ضروريان** قبل التوزيع الفعلي للمحرك.

## خطوات البناء على GitHub من الهاتف

1. ارفع `RM11-WinCore-v0.5.0-source.zip` لجذر المستودع `RM11Cor/RM11-WinCore` على فرع `main`.
2. افتح ملف **جذر المستودع** `.github/workflows/build-apk.yml` وغيّر خطوة فك الضغط فقط إلى:

   `run: unzip -oq RM11-WinCore-v0.5.0-source.zip`

3. احفظ التعديل `Commit changes`. انتظر GitHub Actions `Build ...` لينجح.
4. نزّل آخر Artifact واستخرج `app-debug.apk` ثم اختبره على الهاتف.
5. قد يتطلب Android إزالة إصدار أقدم بسبب تغيّر توقيع البناء، خصوصاً مع `debug`. لا تحذف التطبيق قبل تصدير تقاريرك.

الملف `.github/workflows/build-apk.yml` **الموجود داخل ZIP** ليس هو الذي تشغّله GitHub Actions في جذر المستودع تلقائياً؛ لذلك عليك تعديل ملف الجذر مثل ما سويت بالإصدارات السابقة.

## V2.0 — اختبار Wine الأصلي عبر Box64 (مرحلة بداية الدمج)

أضفنا محاولة تشغيل ملف Wine Linux x86-64 الأصلي (`wine64 --version`) داخل تطبيق Android باستخدام Box64 الموجود من V1.3. يجلب GitHub Actions ملف Wine غير المعدل من حزمة `wine64` في مستودع Ubuntu APT، ويتحقق من معمارية ELF ويضيف بصمة SHA256 ومعلومات الترخيص إلى APK. **فشل الحصول على Wine يوقف بناء V2.0 بدلاً من توزيع APK بدون الملف.**

في القسم 20 يوجد زر واحد «اختبار إصدار Wine الحقيقي». نجاح ظهور سطر `wine-...` ورمز خروج صفر يشير فقط إلى أن **أمر الإصدار عمل**. هذا لا يشمل `libwine`/`wineserver`/مكتبات الجذر/التشغيل الرسومي أو DXVK؛ ليست نسخة تشغّل EXE أو الألعاب. تفاصيل تجارب V2.0 ومحدودياتها في [`V20-WINE-LOADER-AR.md`](V20-WINE-LOADER-AR.md).
