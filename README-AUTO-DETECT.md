# RM11 AutoCore v2.4.5 — offline multi-evidence game analysis

**Read-only Windows game folder inspector**, not a Windows/Proton/FEX runtime.

## What changed from v2.4.4

- New `GameManifestReader` identifies *arbitrary* titles, with no hardcoded game-title mapping, by reading **small, allowlisted local metadata files**: Steam `appmanifest_*.acf`, `steam_appid.txt`, Unity `*_Data/app.info`, GOG `goggame-*.info`, Epic `.egstore/*.item`, Unreal `Config/DefaultGame.ini` and `.uproject`.
- Prefers title from package metadata over guesses based on filename and folder name; PE ProductName remains highest priority and conflicting titles are reported rather than silently resolved.
- Strips generic `Launcher` suffix from EXE name without using a special case for any game. Estimates title, engine, architecture, graphics import hints, platform and local Steam AppID when present.
- Enumerates up to 20,000 entries, 14 folder levels. Reads **at most 64 KiB per recognized metadata file**, no large game assets, while game folder traversal is read-only. SAF inaccessible files are noted by detection uncertainty; never assumes folder enumeration is a checksum validation.
- Stores `schema=2` JSON with metadata source and a clear flag `officialRequirementsVerified=false`.
- Keeps `applicationId=com.rm11.autocore`, increments `versionCode=6`, release signing remains the same stable GitHub Actions configuration and existing secrets.

## What this release cannot know

- Windows/CPU/RAM/VRAM minimum requirements typically **aren't embedded in the game files**. Official requirements require a validated online catalog / official store or developer source and must be distinguished from local hints.
- It cannot assert a game's actual 3D graphics API if the DLL is dynamically loaded or masked by a launcher. A launcher can have different import dependencies from the game engine.
- No evidence in a Steam DLL or local appmanifest proves ownership, DRM requirements or successful launcher integration.
- No versions of Proton/FEX/Turnip/DXVK/VKD3D are recommended as experimentally validated. That needs real execution/measurements on REDMAGIC 11 Pro.
- File picker limitations can prevent scanning protected Android directories. The importer does not modify, copy, run or install any game.

## Build and updates

- Use repository `https://github.com/RM11Cor/RM11-WinCore`, upload ZIP as `RM11-WinCore-v2.4.5-source.zip` on branch `main` to trigger GitHub Actions. The existing workflow selects the last `v*-source.zip` by `sort -V`.
- The `app-release.apk` generated by the **stable-signing** workflow should be signed by the **same private key** already in GitHub Secrets: `RM11_RELEASE_KEYSTORE_B64` and `RM11_RELEASE_PASSWORD`. NEVER upload the signing key or passwords to the public repository.
- Once installed v2.4.4 with the permanent key, v2.4.5 can be installed as an in-place upgrade, given matching certificate and higher `versionCode`.

This source has been Java-compiled and smoke-tested locally, but **Android APK build/installation of v2.4.5 is not yet verified**.
