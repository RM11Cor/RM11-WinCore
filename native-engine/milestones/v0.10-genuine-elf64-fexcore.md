## Physical-device baseline from v0.9

The REDMAGIC 11 Pro user supplied a screenshot showing the original KERNIX
app emitted **KERNIX_X86_MEMORY_WRITE_BRIDGE_EXEC_PASS**. This establishes
an app-reported on-device fixed x86-64 FEXCore memory pointer and two guest
Linux syscalls (`write` then `getpid`), with final guest RAX=Android PID+22.
The narrowly scoped evidence is recorded in
`native-engine/evidence/android-fexcore-v09-x86-memory-write-getpid-ondevice-pass.json`.
This was not a general ELF program loader or proof of Wine.

## New real ELF64 milestone

An independently assembled GNU `as --64` and GNU `ld -pie -nostdlib
--no-dynamic-linker --build-id=none -z max-page-size=0x4000` **x86-64
ELF64 PIE program** now exists, source:
`native-engine/android-guest/kernix_elf64_guest_write_getpid.S`.

This is **not** the previously hardcoded x86 byte sequence placed directly
in host memory. It is a real ELF file with executable `.text`, separate
read-only `.rodata`, PT_LOAD headers and program entry, built independently
by Linux x86-64 GNU toolchain. Its fixed simple code performs the two
Linux guest syscalls and ends with HLT for a bounded integration test.
It does not require external guest libraries, dynamic relocations or glibc.

## Important proof boundary

This is **signed, compiled and CI-verified**, but on-device v0.10
independently compiled ELF execution has **not** yet been observed.

Install v0.10 on REDMAGIC 11 Pro and opt in to:
`Run genuine compiled x86-64 ELF64 via FEXCore (v0.10)`.

Only a genuine device response
`KERNIX_X86_ELF64_EXEC_PASS` (not CI static binaries) would validate
physical-device ELF guest loading and execution. A failed or timed-out run
must remain visible as FAIL/TIMEOUT, never silently promoted.

The loader currently accepts **only one narrow pinned ELF layout**, not
arbitrary applications. There is NO general Linux guest process runtime,
glibc loader, Wine/Proton on Android, Windows EXE execution, Win32 GUI,
DXVK/VKD3D, game rendering, input controls or proven playable PC game.
Future development must independently validate a broader guest memory/ELF
loader, syscall table, filesystem/ABI, Wine runtime and graphics/input
without modifying existing game files or other emulators.
