# KERNIX Android v0.9 — fixed x86 guest memory + two syscall traps

Date: 2026-11-03
Branch: `kernix-native-engine-v1`
Package: `org.kernix.host`
Version: `versionCode=9`, `versionName=0.9-guest-memory-write`

## Motivation

v0.7 was observed on physical REDMAGIC 11 Pro to execute a single FEX x86
Linux `getpid(39)` syscall and return to the correct guest RIP. The v0.8
release established a persistent private Android APK update certificate.
v0.9 adds a new, **strictly bounded guest syscall + memory demonstration**
without affecting the original v0.7 test or claiming Wine/game functionality.

## Actual upstream/native work

Source: `native-engine/android-host/kernix_fexcore_x86_64_write_bridge_probe.cpp`.

The compiled, immutable x86-64 bytecode has two ordered guest Linux syscalls:

1. `mov eax,1; mov edi,1; lea rsi,[rip+20]; mov edx,22; syscall`
   - Linux x86-64 `write(1, address_in_guest_code, 22)` with guest string
     `KERNIX_GUEST_WRITE_OK\n`.
   - Guest instruction offset 22 and next RIP offset 24.
2. `mov ebx,eax; mov eax,39; syscall; add rax,rbx; hlt`
   - Linux x86-64 `getpid(39)`, followed by `RAX=real_android_pid+22`.
   - Second syscall at offset 31 and resumed RIP at offset 33.
3. Immutable guest message begins at offset 37. A valid pass requires:
   exactly **two** syscall handler invocations in that order; exact trap RIP,
   next RIP and syscall numbers; fixed stdout descriptor, message pointer and
   byte length; actual host Bionic `write` of guest-mapped bytes to stdout;
   genuine Android host PID; final genuine FEX guest register `RAX=PID+22`;
   the expected exact stdout and exit code zero.

Fail-closed checks reject unexpected syscall number/count, RIP progression,
guest pointer, buffer bounds or output. It does **not** implement arbitrary
Linux `write` for user-controlled guest code.

The Android frontend `FixedX86WriteProbe.java` starts only the
APK-packaged original ARM64 PIE via `nativeLibraryDir` with a 9-second
deadline. The UI button is labelled
`Test x86 guest memory + write/getpid syscalls (v0.9)`.
No external EXE, ELF, host executable path or untrusted game binary executes.

## Exact proof boundary / next engineering work

**Not yet proven:** user-on-device v0.9 FEX guest code execution and
two-syscall memory bridge. CI compiles and verifies bytes, but cannot prove
physical Android runtime success. It is not a general x86 ELF loader, Wine,
Proton, DXVK/VKD3D, Turnip runtime, Vulkan game swapchain, XInput mapper or
working Windows game emulator.

Next physically measured gate is the v0.9 button output
`KERNIX_X86_MEMORY_WRITE_BRIDGE_EXEC_PASS` on REDMAGIC 11 Pro, versus a
precise `FAIL` or `TIMEOUT`. If that passes, implement a **separately
testable, table-driven, guarded syscall dispatcher** and guest virtual
memory/ELF loader contract. Do not claim arbitrary games work until a
real Android-compatible Wine/PE runtime, native graphics presentation and
game input are independently demonstrated.

Never delete other emulators, game files, or data. Keep this project on the
KERNIX independent branch.
