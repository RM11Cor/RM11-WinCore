## New genuine ELF64 guest and Android runner

New independent GNU `as --64` and `ld -pie -nostdlib --no-dynamic-linker
--build-id=none -z max-page-size=0x4000 -z norelro -e _start` guest
source: `native-engine/android-guest/kernix_elf64_rw_guest.S`.

The new x86 guest is **different** from v0.10: it uses x86-64
`REP MOVSB` to copy a 26-byte message from ELF `.rodata` to
its initially-zero `.data` segment, then calls Linux
`write(1, .data-pointer, 26)` and `getpid(39)` and finishes
with `RAX=host PID+26` before `HLT` in an isolated, bounded child.
This adds a bounded proof of writing guest memory, not just reading it.

- Independently GNU-generated x86 ELF64 PIE SHA-256:
  `8c9ccb70c8d9ee6d149f7afb526e292c96a969e2a29baf7c61f8b6a2fe1938f5`.
  Size 34,344 bytes; 6 program headers, four 16KiB-aligned PT_LOAD
  segments: R, RX, R, RW; entry `0x4000`, fixed guest instruction
  length 58; `REP MOVSB` and two x86 `syscall` instructions at
  offsets 43 and 52. The guest executable is embedded immutably
  in the APK's native ARM64 runner, not loaded from external storage.
- Shared C++ loader `native-engine/android-host/kernix_elf64_loader.h`
  now recognizes two explicit, narrow profiles: v0.10 read-only and
  v0.11 writable-memory copy. New writable-data profile validates
  PT_LOAD bounds, dynamic header length, W^X protection and page
  granularity (4KiB or 16KiB). Its legacy profile remains supported.
  Different GNU ld dynamic table layouts 0xd0/0xe0 bytes are validated
  with the actual guest RIP-relative data pointer, not assumed.
- Original Android ARM64 FEX runner
  `native-engine/android-host/kernix_fexcore_elf64_rw_exec_probe.cpp`:
  SHA-256 `de99967c62c63f00011bf72a587b4bc0019a02f9032640f247c2f016ec3025a9`,
  size 54,320 bytes. Actual pinned upstream Android FEXCore SHA-256
  `f71397bf1bbedd03305c7127e442d674227fa54d15217cc7effb22dbaa9f4b1d`.
- The FEX runner checks initially zero guest `.data`, confirms the
  guest made two ordered syscalls at exact RIP/RCX, strictly validates
  the writable guest pointer and byte count, sends the actual copied
  message via host Bionic `write`, observes real `getpid`, and verifies
  the final guest RAX and actual writable message.
- [Native Android NDK CI 41638897846](https://github.com/RM11Cor/RM11-WinCore/actions/runs/41638897846):
  actual upstream FEXCore linkage, independent guest program assembly,

- Python regression tests `tools/test_kernix_elf64_rw_fixture_check.py`

## On-device qualification not yet complete

**Do not claim v0.11 guest memory execution is proven on a phone.**
Only binary compilation, signing and packaging have been established.
User must install v0.11 and explicitly select the new button:

`Run real x86 ELF64 .rodata → .data memory copy (v0.11)`.

Success marker:
`KERNIX_X86_ELF64_RW_EXEC_PASS`.

An observed FAIL/TIMEOUT is diagnostic evidence, **not** a pass.
This is still a pinned sample ELF64 loader—not a full guest Linux ABI,
dynamic library/ELF process loader, arbitrary external ELF execution,
Wine/Proton, Windows EXE runtime, Vulkan game rendering, controller
support or playable Windows game. Keep all other emulators and game
files untouched.
