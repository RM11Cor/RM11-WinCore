# G0 Linux ARM64 FEX SIGBUS → original libc openat differential (2026-11-07)

**Stage:** one bounded diagnostic-only research gate. **Status:** Linux ARM64 observed; Android/Bionic only compiled; original GNU dynamic-loader completion **not proven**. Do not promote component registry or request phone experiments based on this note.

## Exact evidence / immutable boundaries

- Original upstream FEXCore pin: `FEX-Emu/FEX@02e24ca5c01ed0c864466ed573db347336f70170`; unchanged upstream implementation is the reference. Source-locked original x86 Linux ELF triad (main, GNU ld-linux, libc) and its SHA256 validation are managed by the existing G0 workflows. This note does not introduce a new source pin or distribute binaries.
- Genuine Linux ARM64 TSO-enabled backpatch observation: [run 42379322619](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42379322619) observed `KERNIX_G0_FEX_HOST_JIT_SIGBUS_RESTORED_SOURCE_WINDOW_X86_RIP_CANDIDATE_ONLY guest_rip=0000000801026980 original_interpreter_source_ELF_RX_page=1 original_sha_locked_permission_plan=1 real_FEX_host_PC_reconstructed_to_guest_RIP=1 relocation_store_guest_RIP_not_traced=1`. Source-mapped guest RIP is a candidate, **not** proof of any particular relocation store.
- Independent Linux ARM64 debugger control: [run 42379322755](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42379322755) caught native `SIGBUS` with `si_addr = 0x8000004a9` at ARM64 JIT `ldar x7, [x20]`. This is a native fault witness; its root cause must not be inferred from the signal name alone.
- TSO-disabled A/B diagnostic: [run 42379322765](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42379322765) reported `KERNIX_G0_ORIGINAL_GNU_LDSO_TSO_OFF_SINGLE_PROCESS_DIFFERENTIAL_OBSERVED_NOT_PRODUCTION_PASS execution_returned_or_exited 0` and then the bounded unsupported pathname stop. Disabling TSO is **not** accepted as a production fix and does not prove correct loader or x86 memory semantics.
- After the TSO-enabled JIT backpatch, [run 42379322619](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42379322619) observed an authentic x86 `openat(257)` of the guest-owned stack pathname `/lib/x86_64-linux-gnu/libc.so.6` (bounded preview; `NO_HOST_OPEN`). The SIGBUS-only workflow rejected it as `...OPENAT257_SOURCE_CACHE_PATH_NOT_ALLOWLISTED`. This is the next **probe-policy boundary**, not proof that libc is missing or that arbitrary host filesystem access should be enabled.
- The source at `native-engine/android-host/tests/kernix_g0_original_fex_full_ptload_source_executable_range_arm64.cpp` has a separate explicitly selected, SHA-pinned `SourceFileKernel.DispatchOriginalLdsoPinnedLibcStackOpenat` path for other isolated source-authenticated libc probes. It is guarded by `KERNIX_G0_PROBE_ORIGINAL_LDSO_LIBC_*_ONLY` feature defines; `KERNIX_G0_PROBE_UPSTREAM_SIGBUS_BACKPATCH_ONLY` by itself is deliberately **not** a general libc-open allowlist. Never forward an x86 guest path or raw FD to Android/Linux host.
- Android Bionic cross-build [run 42379322626](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42379322626) failed with exact compiler error `too many arguments to function call, expected 2, have 6` when calling the separate SIGBUS helper. Commit [e2a810e8](https://github.com/RM11Cor/RM11-WinCore/commit/e2a810e8c25f07681da3964eb141331d4a4c87cb) added a six-argument validation overload, and the same Android BUILDONLY workflow [run 42380024760](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42380024760) completed successfully and emitted `KERNIX_G0_ORIGINAL_MAIN_RELRO_SOURCE_ONLY_ANDROID_BIONIC_CROSSLINK_PASS_DEVICE_PENDING`. This fixes the compilation ABI mismatch **only**, not SIGBUS correctness on Android.
- The independent integration workflow [run 42380024581](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42380024581) completed successfully on the same commit. This does not assert original GNU ld-linux main/puts/exit execution on FEX ARM64, Android/JNI runtime, Wine/Proton, DirectX, games or real FPS.

Do not broadly allow guest paths or silently return fake successful host syscalls.
3. Record FEX guest RIP and exact original dynamic-loader progress beyond this `openat`, with bounded negative controls for bad hash, wrong guest path/rights, duplicate FD and non-JIT SIGBUS. A CI green label without actual guest execution/output is insufficient.
4. Continue tracing real original loader relocation writer guest RIPs and all three module RELRO protection transitions against the native x86-64 [main→puts→exit(0) reference run 42368080613](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42368080613). **Do not seal main PT_GNU_RELRO** or claim source-complete linker relocation until exact original guest writes and closure are proven.

## Decision

No speculative FEX upstream patch, broad filesystem allowlist, TSO production disable, phone re-test or game profile change is authorized by these findings. The observations expose two separate boundaries: a real host-JIT fault/recovery diagnostic and a deliberately restricted next guest filesystem call. The cross-build ABI compilation error was independently corrected and tested; full dynamic startup remains open.

## Acceptance reconciliation after independent log review (2026-11-07)

**Do not rerun the already accepted single-open milestone just to turn a green test green again.** The Linux ARM64 [real FEX run 42379322758](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42379322758), using the pinned upstream FEX and exact authenticated original GNU x86 interpreter/libc source, already contains all three real events in strict execution order in one process:

The independent later source-locked libc `read(832)`, `pread64(784)`, `fstat` and ELF mappings have separate Linux ARM64 gates elsewhere in the repository; do not misrepresent independent test variants as one unbroken original dynamic-linker execution through all relocations. A later Linux ARM64 source ledger [run 42379369798](https://github.com/RM11Cor/RM11-WinCore/actions/runs/42379369798) validates *read-only source/target snapshots* but explicitly says original GNU ldso guest store RIPs and complete relocation closure remain untraced.

Preserve refusal to seal original main RELRO until loader closure has an actual runtime witness. This is a **planned gate, not a passed test**.

This correction supersedes the earlier suggestion above to create the SIGBUS→libc synthetic-FD join as though no accepted Linux run existed. No new Android runtime, Wine/Proton, Vulkan or gaming proof is implied.
