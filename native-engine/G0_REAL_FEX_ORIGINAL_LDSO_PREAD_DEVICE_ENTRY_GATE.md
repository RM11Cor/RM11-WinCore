# G0 — authentic FEX guest pread64 of verified original ld-linux

The on-phone fixed GNU ELF `write`+`getpid` is already a **bounded
physical Android PASS**, documented separately.

## New actual guest-code integration (Linux ARM64 reference)

- Source-pinned upstream FEXCore commit:
  `02e24ca5c01ed0c864466ed573db347336f70170`.
- Independently source-attested original Linux x86_64 guest files from
  GitHub Actions run `41846530666`: main ELF, real
  `ld-linux-x86-64.so.2`, real `libc.so.6`. All SHA256 and exact
  sizes are rechecked; the private root refuses symlinked files.
- Current G0 production `OriginalGuestSnapshotTable` revalidates the
  actual three original sources and stores immutable, PROT_READ
  anonymous copies behind guest virtual file descriptors 3/4/5.
- A **GNU-as** x86-64 guest `_start` executes one real
  `pread64(17, fd=4, dest=<attested guest RW VMA>, n=64, off=0)` in
  original FEXCore on a genuine Linux AArch64 runner. The fourth x86
  syscall argument is explicitly zeroed in **R10**, not RCX.
- The original upstream FEX `CpuStateFrame` callback goes through the
  already verified C1/C2 x86-64 register+stack provenance check.
  It dispatches the guest request to the immutable file table,
  stores the real 64-byte return in guest RAX, and returns to the x86
  instruction stream.
- The actual x86 instruction `movzbl (%rsi), %eax` after syscall
  loads the byte 0x7f from **the guest buffer**. Host acceptance
  requires both guest `RAX==127` after bounded HLT and that the
  returned buffer contains the real ELF64 little-endian
  `\x7fELF` identity and `e_machine==EM_X86_64`.
- Neither raw x86 syscall numbers nor original file descriptors are
  forwarded to the AArch64 kernel. W^X executable code, separate
  writable guest stack and data, original low-canonical guest VA
  checks, and a bounded disposable FEX session remain required.

## Pass/fail gate

The evidence must be generated by **CI on real Linux ARM64**, not
source-only checks: successful upstream original FEX build, SHA256
source files, actual GNU-as assembled original x86 guest code,
exact source-verified syscall registers from a *live* FEX callback,
real copied ld-linux source bytes, and genuine x86 guest instruction
reading the resulting 0x7f into RAX before reaching HLT. No
`PASS` may be awarded merely for linking the host binary.

**This is not running a dynamic ELF guest:** the original ld-linux
bytes are read as **data**, not executed as the guest interpreter.
Original ldso instructions, glibc startup, `PT_INTERP`, TLS,
relocations, IFUNC, x86 guest `exit_group`, Wine, Proton, or any
Windows PC game remain out of scope.

**After this Linux gate passes**, use the same source-built, exact
three-file table and authenticated live FEX guest callback under
Android/Bionic ARM64 with separate original signed G0 child process.
Do not claim Android success until phone evidence. Do not touch
stable KERNIX v0.27 or its game data. If this gate fails, fix its
specific step without relaxing guest pointer provenance or
disabling app security.
