# CarX PC Runtime — تحديثات APK الرسمية

صفحة الإصدارات: https://github.com/RM11Cor/RM11-WinCore/releases

## القواعد الثابتة
- نستخدم نفس معرف التطبيق: `com.r4.carxpc` في جميع الإصدارات.
- نزيد `versionCode` في كل إصدار: R1=1 وR2-A=2، ثم R2-B=3 وR2-C=4 وهكذا.
- نوقّع جميع APKs الجديدة **بنفس مفتاح إصدار خاص ومحمي**؛ لا نولّد Debug keystore جديداً لكل بناء.
- الملفات ستُنشر كأصول GitHub Releases مع ملف SHA-256، وليس فقط GitHub Actions Artifacts.
- لا ننشر المفاتيح الخاصة أو كلمات المرور في المستودع العام.

## إعداد مطلوب لمرة واحدة
أنشئ ملف توقيع PKCS12 خاصاً باسم مستعار `carxpc` وكلمة مرور قوية، واحتفظ بنسخة احتياطية آمنة. أضف إلى GitHub Settings → Secrets and variables → Actions:
1. `CARX_SIGNING_KEYSTORE_B64`: المحتوى Base64 لملف PKCS12.
2. `CARX_SIGNING_PASSWORD`: كلمة المرور نفسها للملف والمفتاح.

بعد أول إصدار موقّع، أضف بصمة شهادة SHA-256 العلنية في Repository variable: `CARX_EXPECTED_CERT_SHA256`، ليرفض البناء أي توقيع مختلف.

## إصدار جديد
- أنشئ Git tag من فرع مشروع CarX، مثل `carx-pc-v0003-r2b`. سير العمل `.github/workflows/carx-pc-runtime-release.yml` يبني APK موقّعاً وينشره في Releases إذا نجحت الاختبارات.
- الإصدارات التشخيصية تُنشر كـPre-release، ولا توصف على أنها لعبة قابلة للعب.

## الانتقال من R1 / R2-A
شهادة R1 تختلف عن شهادة R2-A، وليس لدينا مفتاح التوقيع الخاص لأي منهما. لهذا يلزم حذف النسخة القديمة **مرة واحدة** عند الانتقال إلى أول إصدار رسمي ثابت التوقيع. قبل الحذف، صدّر التقارير واحفظ الإعدادات؛ حذف التطبيق يمحو بياناته الداخلية. بعد تثبيت أول إصدار بالمفتاح الثابت، تصبح الإصدارات التالية قابلة للتثبيت فوقه مع الحفاظ على بيانات التطبيق.

**الحالة الحالية:** قناة الإصدار الآمن جهزت كمصدر داخل فرع مستقل، لكن لا يوجد إصدار جديد منشور منها ولا يمكن ضمان تحديث مباشر قبل ضبط أسرار التوقيع وبناء إصدارين متتاليين بهوية واحدة.
