# CarX PC Runtime R3-C4 — تقدم GNU libc عبر pread64 حقيقي

## إثبات الهاتف القادم من R3-C3
- الجهاز NX809J، Android 16، ARM64.
- نجاح محدود مثبت بتقرير المستخدم `CarX_PC_R3C_Diagnostics (3).json`:
  - `libc` الأصلية مفتوحة افتراضياً داخل نظام ملفات الضيف بمعرّف `fd=100`، من دون تمرير مسار إلى host.
  - انتهى `read(fd=100, 832)` بشكل صحيح، وتحققت ترويسة ELF64 في ذاكرة ضيف x86-64 مملوكة.
  - `SIGBUS` الخاص بـJIT تعامل مع `delta=0` وأعاد التنفيذ بشكل صحيح.
  - الاستدعاء التالي الذي كشفه المصدر الأصلي كان `pread64(17)` بمعاملات `fd=100, buf=0x80300eb40, count=784, offset=64`.
  - خرج الاختبار المحدود برمز `117` عند الاستدعاء غير المدعوم؛ لم تبدأ glibc كاملة.
- ملاحظة: `success=true` داخل التقرير متعلق بالبوابة السابقة فقط، لا يعني تشغيل اللعبة أو كامل `ld.so`.

## التنفيذ الجديد
لا نغيّر FEX أو ملفات DLL أو Vulkan. فعّلنا تعريف KERNIX الموجود:
`KERNIX_G0_PROBE_ORIGINAL_LDSO_LIBC_STACK_PREAD_ONLY`
بدلاً من `..._STACK_READ_ONLY`.
المصدر نفسه يحتوي `DispatchOriginalLdsoPinnedLibcPreadToStack` مع تحقق:
1. وجود `fd=100` مفتوح أصلياً بواسطة عملية الضيف.
2. `requested=784` و`offset=0x40` من حقل x86 `R10`.
3. صلاحيات `RW` لمدى ذاكرة الضيف وكامل حدود القراءة.
4. نقل بيانات ملف `libc.so.6` المثبتة بالبصمة إلى الذاكرة الموثقة، من دون استدعاء host `pread` بمدخلات ضيف غير موثوقة.
5. ظهور العلامة الأصلية `KERNIX_G0_REAL_ORIGINAL_GNU_LDSO_LIBC_SYNTHETIC_FD_PREAD64_784_SOURCE_OFFSET_40_OWNED_GUEST_STACK_PASS_NO_HOST_PREAD`.

## شروط الاعتماد
- GitHub CI: مصدر كامل مطابق، نفس `libFEXCore.so`، نفس إصلاح `SIGBUS`، بنية ARM64 Bionic، فحص توقيع وبصمة APK النهائي مع رقم إصدار 11.
- الجهاز: تظهر علامة القراءة المحددة أعلاه بعد علامة `read(832)`، ثم يكتشف الاختبار الاستدعاء الأصلي التالي. يُسجّل رقم الاستدعاء ولا نفترضه مسبقاً في تقرير المستخدم.
- لو خرجت العملية `117` بعد القراءة الجديدة، تُعتبر **بوابة R3-C4** ناجحة فقط. إذا انتقل الخطأ إلى موضع آخر نحلّ الموضع الجديد ولا نتراجع لفحوص R1–R3-C3.
- ليست شهادة اكتمال `glibc` أو `Wine` أو `DXVK` أو تشغيل `CarX Street`.

**الهدف اللاحق المحتمل:** `fstat` أو `mmap` بحسب أول استدعاء أصلي يظهر بعد `pread64`، مع الاستفادة من مصادر KERNIX السابقة.
